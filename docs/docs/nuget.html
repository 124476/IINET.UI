NuGet и публикация

Пользователь должен иметь возможность установить весь набор компонентов одной командой: dotnet add package IINET.UI. Для этого используется агрегирующий (meta) NuGet-пакет.

Статус: планируется.

Пакет IINET.UI ещё не опубликован. Команда установки станет рабочей после публикации компонентных пакетов и агрегирующего пакета в NuGet или другом настроенном NuGet feed.

Как это будет выглядеть для пользователя

dotnet add package IINET.UI

Потребитель не указывает каждый компонент отдельно. NuGet скачивает агрегирующий пакет и его зависимости.

Схема зависимостей

IINET.UI                 (агрегирующий пакет)
└── IINET.UI.Calendar    (компонент)
    └── IINET.UI.Core   (общее ядро)

В дальнейшем агрегирующий пакет будет дополнен зависимостями на другие компоненты, например IINET.UI.Charts или IINET.UI.Gantt. Пользователь по-прежнему будет устанавливать только IINET.UI.

Пример проекта агрегирующего пакета

Шаблон находится в packaging/IINET.UI/IINET.UI.csproj.example. В нём отключается включение выходной сборки и добавляется зависимость на пакет календаря:

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <PackageId>IINET.UI</PackageId>
    <Version>0.1.0</Version>
    <Description>Aggregate package for IINET.UI components.</Description>
    <IsPackable>true</IsPackable>
    <IncludeBuildOutput>false</IncludeBuildOutput>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="IINET.UI.Calendar" />
  </ItemGroup>
</Project>

Так как в репозитории используется Central Package Management, версия IINET.UI.Calendar должна быть объявлена в общем Directory.Packages.props, например:

<PackageVersion Include="IINET.UI.Calendar" Version="0.1.0" />

Порядок публикации

  1. Собрать и опубликовать IINET.UI.Core.
  2. Собрать и опубликовать IINET.UI.Calendar, проверив, что его .nuspec содержит зависимость на Core и необходимые пакеты Avalonia.
  3. Собрать агрегирующий IINET.UI, который зависит от компонентных пакетов.
  4. Опубликовать агрегирующий пакет.
  5. Проверить установку в чистом тестовом Avalonia-приложении командой dotnet add package IINET.UI.

Почему не одна DLL?

Решение может состоять из нескольких NuGet-пакетов, но пользователь не обязан устанавливать каждый. Агрегирующий пакет — это небольшой пакет зависимостей: он сообщает NuGet, какие компонентные пакеты нужно установить транзитивно. Такой подход упрощает рост библиотеки без объединения всего исходного кода в одну сборку.

Версии

Рекомендуется поддерживать согласованную версию релиза для Core, Calendar и агрегирующего пакета (например, 0.1.0) либо явно фиксировать совместимые диапазоны зависимостей. NuGet поддерживает диапазоны версий; их нужно задавать осознанно и проверять в итоговом .nuspec.

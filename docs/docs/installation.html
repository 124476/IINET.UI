Установка и подключение IINET.UI

IINET.UI состоит из отдельных проектов и компонентов. Пока NuGet-пакеты не опубликованы, подключайте нужный проект напрямую; после публикации агрегирующего пакета библиотеку можно будет установить одной командой.

Важно: команда dotnet add package IINET.UI пока не работает из nuget.org — агрегирующий пакет ещё не выпущен.

1. Подключение проекта из репозитория

dotnet add YourApp.csproj reference path/to/IINET.UI.Calendar.csproj

В репозитории IINET.UI проект Demo подключается так:

dotnet add samples/IINET.UI.Demo reference src/IINET.UI.Calendar/IINET.UI.Calendar.csproj

2. Зависимости приложения

Потребительское приложение должно использовать совместимые версии Avalonia, Avalonia.Desktop и выбранной темы. Текущая цель проекта — net8.0; нижняя версия Avalonia, на которую ориентируется разработка, — 11.0.0. Совместимость с конкретным выпуском следует проверять сборкой и запуском.

3. Подключение темы компонента Calendar

В проекте IINET.UI.Calendar.csproj убедитесь, что ресурс темы включён:

<ItemGroup>
  <AvaloniaResource Include="Themes/**/*.axaml" />
</ItemGroup>

В App.axaml приложения подключите словарь:

<Application.Resources>
  <ResourceDictionary>
    <ResourceDictionary.MergedDictionaries>
      <ResourceInclude
        Source="avares://IINET.UI.Calendar/Themes/Generic.axaml" />
    </ResourceDictionary.MergedDictionaries>
  </ResourceDictionary>
</Application.Resources>

Не удаляйте существующую секцию Application.Styles: тема календаря и тема приложения решают разные задачи.

4. Использование Calendar в AXAML

<Window
  xmlns="https://github.com/avaloniaui"
  xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
  xmlns:calendar="using:IINET.UI.Calendar.Controls"
  x:Class="YourApp.MainWindow">

  <calendar:Calendar
    HorizontalAlignment="Stretch"
    VerticalAlignment="Stretch"
    SelectedDate="{Binding SelectedDate, Mode=TwoWay}"
    DayContents="{Binding CalendarMarks}" />
</Window>

5. Установка всей библиотеки

dotnet add package IINET.UI

Когда агрегирующий пакет будет опубликован, он подтянет компонентные пакеты как NuGet-зависимости. Подробности — в разделе NuGet и единая установка.
